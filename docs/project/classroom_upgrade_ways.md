
## 总体判断

> **已经拥有完整课堂能力，但仍在用“功能展览”的方式组织它，而不是围绕学生当下要完成的一个学习目标组织它。**

功能覆盖面很强，但首版同时把七阶段流程、AI 状态、教材系统、记忆系统、掌握度、音频、语法测试和能力推荐全部暴露给用户，导致认知负担明显。

最值得做的不是继续增加模块，而是进行一次**课堂收敛**。

# P0：建议立即修复的问题

## 1. “上一环节”会错误地将当前环节标记完成

目前 `moveToPhase` 无论向前还是向后跳转，都会执行：

```ts
setCompletedPhaseIds((current) => new Set(current).add(phase.id))
```

而 `goPrevious` 也直接调用 `moveToPhase(phaseIndex - 1)`。这意味着学生点“上一环节”复习时，当前环节会被自动判定完成。

这是学习数据污染问题，不只是 UI 问题。

建议拆成：

```ts
const navigateToPhase = (nextIndex: number) => {
  setPhaseIndex(clamp(nextIndex))
}

const completeAndContinue = () => {
  setCompletedPhaseIds(current => new Set(current).add(phase.id))
  navigateToPhase(phaseIndex + 1)
}
```

左侧阶段导航和“上一环节”只负责导航；只有明确完成动作才能写入完成状态。

---

## 2. 学生可以绕过所有学习门槛直接完成课堂

桌面端左侧七个阶段全部可点击，点击时还会将离开的阶段标记完成。

移动端底部“下一环节”也始终开放，独立于各环节内部的完成条件。

结果是：

* 单词卡一张没翻，也能进入下一环节
* 音频一句没听，也能继续
* 教材题没有作答，也能进入挑战
* 桌面端可以直接点击“课堂总结”

建议建立统一的阶段门禁：

```ts
type PhaseGate = {
  canContinue: boolean
  reason?: string
  completionEvidence?: string[]
}
```

例如：

* 词汇：翻看至少 4 张，或选择“这些词我已经会了”
* 语法：完成辨析和迁移表达
* 听力：至少完成一次连续播放，或精听 3 个关键句
* 教材题：至少保存一次答案
* 挑战：提交并获得反馈

门禁不应要求学生机械完成全部内容，但必须留下最小学习证据。

---

## 3. 关闭课堂会同时清空当前 `dailyLesson`

关闭逻辑为：

```ts
onClose={() => {
  setClassroomPlan(null)
  setDailyLesson(null)
}}
```

这可能导致 UI 在当前会话中丢失“可恢复课堂”的判断依据。虽然 episode ID 存在 localStorage，重新进入时可能恢复，但页面上的 resume 状态不能立即反映。

建议区分：

* `closeClassroom()`：仅关闭沉浸式窗口
* `discardLesson()`：显式放弃当前课堂
* `finishLesson()`：完成并清理运行时数据

学生点关闭时应显示轻量提示：

> 进度已保存，可稍后继续。

不要让“关闭界面”等价于“清空课程运行态”。

---

## 4. 关闭按钮重复，且 Escape 没有处理中间状态

顶部同时有“返回箭头”和“X”，两者功能完全相同。

此外，任意时刻按 Escape 都会直接退出。

建议：

* 只保留一个退出入口
* 正在 AI 诊断、保存中或有未提交文本时，Escape 第一次只提示
* 已完成自动保存时直接退出
* 顶部明确显示“已保存于 10:42”，比模糊的“进度已同步”更可信

# P1：产品体验上的主要优化

## 5. “七阶段课堂”适合系统，不适合成为用户的主要心智模型

当前入口直接强调：

* 七阶段课堂
* 语法掌握证据
* 教材原声听辨
* PDF 原题作答
* AI 实时诊断
* 进度自动保存

这是典型的“向用户解释产品内部结构”。

七年级学生真正关心的是：

> 我今天要学什么？
> 大概要多久？
> 我现在该做哪一步？
> 做完之后我会得到什么？

建议入口改成：

**今天用 22 分钟学会：问候和自我介绍**

下方只显示：

* 5 个新词
* 1 个核心句型
* 1 段教材听力
* 2 道教材原题

“七阶段”“Memory 联动”“PromptExecutor”应留在开发和教师侧，不应成为学生侧价值表达。

---

## 6. 首屏同时出现“任务、Big Question、语法、学习证据”，信息焦点过多

课堂简报首屏当前包含：

* 本课任务
* BIG QUESTION
* 今天必须掌握的语法
* 三条可观察学习证据
* 进入课堂按钮

这些概念本质上存在重叠。

建议只保留三级结构：

### 今日目标

能完成一段简单的问候与自我介绍。

### 今天会练

5 个词 · be 动词 · 1 段对话 · 2 道教材题

### 完成标准

最后能独立说出或写出一段自己的介绍。

“Big Question”更适合探究式课程，不适合每个普通英语单元机械套用。

---

## 7. 视觉语言过于“AI 产品”，缺少“教材课堂”的稳定感

界面大量使用：

* 深色全屏背景

* 多重径向渐变

* 紫、青、粉、橙多色渐变

* 大面积发光和阴影

* `AI COACH`

* `AI CHECKPOINT`

* `AI 实时编排`

这很容易产生“科技演示页”的感觉，而不是可连续使用几十分钟的学习工具。

建议视觉层级调整为：

* 教材内容：浅色或纸张色背景
* 操作区：中性白或深灰
* AI 建议：单一紫色辅助色
* 正确反馈：绿色
* 注意与错误：琥珀色，不大量使用红色
* 每个页面最多一个渐变主视觉

尤其教材题区域已经使用白底图片，与整个深色霓虹环境割裂。

可以考虑“数字教材桌面”概念：左边教材页，右边学习笔记和 AI 提示，而不是游戏关卡式舞台。

---

## 8. “AI”出现次数太多，价值反而被稀释

当前可见文案包括：

* AI 实时编排
* AI COACH
* AI 做题教练
* AI 实时诊断
* AI CHECKPOINT
* AI 正在评阅
* AI 教材课堂

产品不需要在每个组件上重复证明自己有 AI。

建议只在 AI 真正产生动态结果的位置标记：

* “根据你的答案生成”
* “个性化提示”
* “针对本题的诊断”

其余位置使用教学动作命名：

* 课堂简报
* 做题提示
* 检查答案
* 课堂挑战
* 学习总结

---

## 9. 词汇翻卡更像交互装饰，学习效度不足

当前词汇卡只有正反面翻转和“点亮数量”。

主要问题：

* 翻卡不等于掌握
* 颜色随机但不表达知识类型
* 没有发音
* 没有“不认识 / 模糊 / 已掌握”的反馈
* `flipped.size` 被当作学习成果

建议改为三态微诊断：

| 学生操作 | 系统行为           |
| ---- | -------------- |
| 认识   | 降低后续出现频率       |
| 模糊   | 在后续听力和教材题前再次提示 |
| 不认识  | 加入本课重点词        |

卡片翻转只作为查看释义，不作为掌握证据。

你此前已经实现“太简单，标记已掌握”的词汇机制，这里应直接复用同一个学习语义，而不是创建第二套“点亮”体系。

---

## 10. 小学复现词依赖 hover，不适合移动端

文案明确写着“悬停可查看释义”。

移动设备没有稳定 hover 行为。

建议改为：

* 点击词语弹出底部释义
* 长按播放发音
* 一键标记“忘了”
* 默认只展示 6–8 个，展开后查看全部

---

## 11. 教材题要求学生把整页答案写进一个 textarea，交互成本很高

当前说明：

> 按题号填写，例如：1a: ...；1b: ...

这对七年级学生不自然，也会让 AI 解析答案变得不稳定。

更好的方向：

* 根据教材页自动识别题号
* 右侧生成逐题输入框
* 选择题直接显示选项
* 连线题允许简单配对
* 听力题支持“没听清这一句”
* 实在无法结构化时，再提供整页自由输入

技术上，提交已经具备教材页抽取和 schema 约束能力，因此可以将“题目结构提取”作为 compose 阶段的一部分，而不是把格式化责任交给学生。

---

## 12. AI 诊断结果没有转化为直接可执行的界面

后端返回了：

```ts
next_action:
  | 'relisten'
  | 'review_vocabulary'
  | 'review_pattern'
  | 'continue'
```

但 UI 只把它显示成一个英文小标签。

这是浪费了已有结构化能力。

建议直接映射成按钮：

* `relisten` → **重听相关句子**
* `review_vocabulary` → **复习这 3 个词**
* `review_pattern` → **回看句型**
* `continue` → **继续下一题**

AI 诊断的最佳形态不是一段文本，而是**让下一步动作立即发生**。

# P2：代码结构和可维护性

## 13. `GenerativeClassroom.tsx` 已达到 506 行，继续扩展会迅速失控

单文件同时负责：

* 模态窗口
* 阶段导航
* 自动保存
* 音频播放器
* 时间轴
* 教材任务
* AI 诊断
* 语法实验室
* 挑战
* 总结

建议拆分：

```text
GenerativeClassroom/
├── GenerativeClassroom.tsx
├── useClassroomProgress.ts
├── useTextbookAudio.ts
├── useClassroomNavigation.ts
├── ClassroomHeader.tsx
├── ClassroomRail.tsx
├── phases/
│   ├── BriefingPhase.tsx
│   ├── VocabularyPhase.tsx
│   ├── GrammarPhase.tsx
│   ├── AudioPhase.tsx
│   ├── TextbookPhase.tsx
│   ├── ChallengePhase.tsx
│   └── ReflectionPhase.tsx
└── classroom.types.ts
```

尤其自动保存应成为独立 hook，并包含：

* dirty 状态
* retry
* lastSavedAt
* unload protection
* 乐观更新
* 失败队列

---

## 14. 阶段由字符串 `kind` 控制，缺少类型约束

目前：

```ts
phases: Array<{
  id: string
  kind: string
  ...
}>
```

但渲染依赖固定值：

* `briefing`
* `cards`
* `grammar`
* `audio`
* `textbook`
* `challenge`
* `reflection`

建议使用 discriminated union：

```ts
type ClassroomPhase =
  | BriefingPhase
  | VocabularyPhase
  | GrammarPhase
  | AudioPhase
  | TextbookPhase
  | ChallengePhase
  | ReflectionPhase
```

否则服务端一旦返回拼写错误或新类型，页面会出现空白阶段。

还需要明确 unknown phase fallback，而不是静默不渲染。

---

## 15. 自动保存状态存在误导

初始状态为 `idle`，但头部会显示“进度已同步”；只有 `saving` 和 `offline` 有特殊文案。

实际语义应区分：

* 尚未修改
* 有未保存修改
* 保存中
* 已保存
* 保存失败
* 离线等待同步

并显示最后保存时间。

---

## 16. 测试主要验证文案出现，没有验证关键行为

当前测试重点是：

* 是否出现任务文本
* 是否出现 Grammar Lab
* 是否出现教材题和 AI 教练
* 图片 URL 是否正确

应优先补充：

1. 点“上一环节”不会标记完成
2. 未满足门禁不能继续
3. 保存失败后显示重试
4. 恢复课堂时进入正确阶段
5. 切换教材题不会丢失答案
6. AI 请求重复点击会被抑制
7. Escape 在 dirty 状态下不会直接退出
8. 空 phases、未知 kind、无音频、无教材题均有降级界面

# 一个更有创造性的产品方向

## 将“七阶段课堂”改造成“AI 导演式课堂”

当前系统把七个环节固定平铺。更适合 Agent 产品的方式是：

> **课堂不是固定七步，而是一条根据学生表现动态缩短、展开或回跳的学习路径。**

例如学生进入课堂后：

### 1. 30 秒热身诊断

系统用一个问候问题判断：

* 单词是否认识
* be 动词是否稳定
* 是否能组织一句完整表达

### 2. 动态生成路径

**基础薄弱学生**

```text
词汇唤醒 → 句型示范 → 语法辨析 → 听力 → 教材题
```

**基础一般学生**

```text
快速词汇检查 → 听力 → 教材题 → 针对性语法纠错
```

**已掌握学生**

```text
教材挑战 → 真实表达迁移 → 提前完成
```

### 3. UI 不再显示七个固定阶段

改成：

```text
今天的路线
● 已完成：快速热身
● 当前：教材听力
○ 接下来：根据表现决定
```

这样 Agent 的价值才真正体现出来：不是“AI 给固定流程填内容”，而是“AI 决定下一步最值得学什么”。

# 建议的实施顺序

## 第一轮：修正确性

1. 修复返回上一环节却标记完成
2. 引入阶段门禁
3. 关闭课堂不清空运行态
4. 增加 dirty/save 状态
5. 修复 hover-only 交互

## 第二轮：降低认知负担

1. 首屏只保留一个学习目标
2. 减少“AI”字样
3. 七阶段导航改成“当前 / 已完成 / 下一步”
4. 教材题改成逐题输入
5. AI `next_action` 变成真正的操作按钮

## 第三轮：体现 Agent 差异

1. 增加 30 秒热身诊断
2. 阶段支持动态插入、跳过和回补
3. 学习路径根据 Mastery 和 Memory 编排
4. 总结不再只统计完成量，而是展示：

   * 今天新形成的能力
   * 暴露的薄弱点
   * 下次第一项复习内容

---

## 最核心的一条建议

不要继续把更多教学模块塞入这间课堂。

下一次提交应围绕一个目标：

> **让学生进入后不需要理解系统结构，只需要知道现在做什么，以及为什么做。**

当前版本已经完成了“把所有能力放进一个课堂”；下一阶段应完成“让课堂替学生隐藏系统复杂度”。
