# 异步练习题池：面试讲法

## 60 秒版本

原来的问题不是单纯“LLM 慢”，而是把生成、校验、审题放在用户请求里，延迟、可靠性和题目质量互相绑死。我把它改成 PostgreSQL 持久化题池加独立 Worker：API 只查题池并做个性化选题，有题就立即返回当前最佳 8 题，同时幂等触发补池；完全没题才返回 202，前端按建议间隔轮询。

Worker 用 `FOR UPDATE SKIP LOCKED`、任务租约、有限重试和 active dedupe index 支持多实例安全领取。生成不是直接写库，而是 coverage plan、结构化候选、确定性门禁、独立 LLM reviewer 四层链路。Reviewer 给知识对齐、可作答性、自然度、干扰项、解析和创新度六维评分，其中知识对齐和可作答性低于 0.75 直接拒绝。题池目标 24、低于 16 自动补池，选题再结合质量、学习者掌握度、题型和知识点多样性。

这样用户延迟从“等待 LLM”变成“数据库查询”，进程重启也不丢任务，并且低质量旧题会在高质量替代题成功后逐步退出。

## 为什么这样决策

### 为什么不是让接口一直等

LLM 调用的尾延迟高，而且候选生成和审题是两次结构化调用。同步等待会占住连接、容易超时，用户刷新还会重复触发生成。把它移到 Worker 后，API 延迟与模型延迟解耦。

### 为什么不是 FastAPI BackgroundTasks

`BackgroundTasks` 适合轻量、可丢失的进程内善后，不适合分钟级生成任务：进程重启会丢、多个 API 实例难协调、没有天然租约/重试/去重/审计。任务表是这条业务链路的 durable state。

### 为什么先用 PostgreSQL，不直接上 Celery/Redis

当前吞吐是“按教材单元偶发补池”，不是海量实时任务。PostgreSQL 已经是系统真相源，用行锁和部分唯一索引即可满足领取、去重、恢复与审计，部署复杂度最低。Redis 可以以后做热点状态缓存，但不能成为唯一题目来源。若任务量、优先级、定时调度和跨服务消费明显增长，再迁 Celery、Dramatiq 或 Temporal。

### 为什么已有 3–6 题也要立即返回

可用且经过验收的少量题，比让用户等待或用坏模板凑 8 题更好。响应标记 `refreshing`，本次先学习，后续请求自然拿到补池后更高质量的组合。这是 stale-while-revalidate 在题库场景中的应用。

## 关键工程点

1. `dedupe_key = hash(unit + knowledge input hash + generator version)`，同一输入只允许一个 active 任务。
2. Worker 领取使用 `FOR UPDATE SKIP LOCKED`，多实例不会领取同一行；租约过期后任务可恢复。
3. 任务只有限重试，错误摘要和接受/拒绝数留在运行记录中，避免无限 poison job。
4. 生成题必须经过 PromptExecutor、schema 和双质量门禁，不能让原始 LLM 输出直接污染学习者题库。
5. 新题写入与运行状态在同一数据库事务提交；失败则回滚，不暴露半批题。
6. 旧题不是先删后生。只有新批次达到最低可用数，才归档未审核的旧生成题。
7. API 的 200/202 和 `pool.status` 表达“是否已有内容”与“后台是否在工作”，前端不需要猜状态。

## 面试官追问

### 如果两个用户同时点击怎么办？

两次请求都可以读现有题池，但 active dedupe 部分唯一索引保证相同单元、知识输入和生成器版本只有一个 `queued/running` 任务。选题仍可因各自 mastery 不同而返回不同组合。

### Worker 进程挂了怎么办？

任务已提交在数据库，不随 HTTP 进程消失。`running` 任务带 `lease_expires_at`，租约过期后其他 Worker 可以重新领取。最大尝试次数后变成 failed，避免无限重试。

### 为什么质量分不能直接取 Top 8？

纯 Top 8 容易全是同一知识点或同一题型，也可能难度不适合当前学习者。系统先做质量硬门槛，再把质量与 mastery 目标难度结合，最后用约束选择保证题型和知识点覆盖。

### LLM 自己审自己可信吗？

不能完全信，所以先用确定性规则排除结构错误、答案泄露、非法知识点和选项问题；LLM reviewer 只负责自然度、语境连贯、歧义等规则难覆盖的问题。Prompt、schema、eval 和运行记录相互独立。生产上还可采用更强 reviewer 模型和人工抽检。

### 如何证明质量真的提升？

第一层是离线指标：schema pass、规则通过率、review accept、六维平均分、重复率和覆盖率。第二层是真实学习指标：跳过率、歧义反馈、首次正确率、题目区分度、重试与提示使用、答题后 mastery 增益。静态 LLM 分数只是准入信号，不能代替真实行为数据。

### 最大的未完成项是什么？

生产级还应增加租约心跳/ownership token、失败任务告警、Dev Console 题池观测，以及基于真实作答数据的题目校准和自动淘汰。这些是明确的演进路径，不影响当前“异步、持久化、可降级、可审计”的主链路。

## 简历表达

> 将同步 LLM 练习生成重构为 PostgreSQL 持久化题池与独立 Worker：通过 SKIP LOCKED、任务租约、幂等去重和有限重试实现可恢复后台生成；设计 deterministic gate + independent LLM review 六维质量评分，并结合 mastery、题型和知识点约束返回个性化 Top 8，使 API 可立即返回已有题或以 202 异步轮询。
